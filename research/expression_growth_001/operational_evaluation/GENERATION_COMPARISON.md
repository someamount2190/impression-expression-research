# Bounded generation comparison

`run_generation_comparison.py prepare` freezes one lexical task per each of the ten families in the existing 30-task balanced slice. It creates new artifacts and refuses to replace an artifact with changed content. The frozen 30-task and 100-task manifests are inputs only.

The three arms are A: unchanged pinned [BASE_MODEL]; B: the same [BASE_MODEL] with the newly trained layer-27 Q-projection adapter; C: B with interpreter-loadable accepted macros included in its available declarations. A and B use identical prompts. C adds only the available macro declarations. All arms use the same local HF checkpoint, tokenizer, CPU BF16 eager inference, deterministic generation settings, and static validator. The adapter is applied by a forward hook; base parameters are not edited. A passed fresh-process adapter verification and matching adapter file hash are required for B/C.

The default bounded matrix is 10 tasks × 3 arms, at most 512 generated tokens and 180 seconds per call, with a 5,400-second total wall-clock allowance including model load. Set `--cpu-threads N` to choose the PyTorch intra-op thread count; all arms within one run share the setting, which is recorded in the receipt. The generation API checks its timeout between generation steps, so a long prefill can exceed the per-call target before generation returns. Calls are interleaved by task. Compare only task IDs completed by every requested arm, and report partial coverage with its exact denominator. Ten tasks are too few for a precise performance estimate; no 100-task rate should be extrapolated.

The harness never dispatches actions. `raw_outputs.jsonl` preserves full prompts, raw model text and generated token IDs, local tokenizer counts, generation time, RAM snapshots, and static validation results. `target_plan` and target hashes are excluded from messages by an explicit field allow-list. The scorer uses targets only after generation to compare the first operation signature. That metric does not establish semantic action correctness. Strict JSON is validated without repair, extraction, fallback, or normalization. Dependency validity is a static validator result. Hallucinated receipt-key counts cover parsed JSON keys, not every unsupported claim in prose. Completion, recovery, failure loops, macro transfer, and tool latency are untested (`null`). No provider usage is manufactured.

The full HF BF16 inference path has not been parity-verified against IMPRESSION's streamed CPU arithmetic, which accumulates projections in FP32. The A/B/C generation comparison controls that path across arms, but cannot replace the streamed adapter parity test. Inference keeps the full BF16 model resident and is distinct from the bounded streaming training path. A RAM preflight includes model size, 2 GiB overhead and the established 20% reserve; available RAM is checked after load and before every call.

The discovery `learned_library/library.json` uses `proposals`/`canonical_ast`, while the typed interpreter loader requires `macros` containing a typed body, primitive expansion and validation hash. `discovery/export_interpreter_library.py` creates the separate loader-compatible `learned_library/interpreter_library.json`. That file loaded one accepted macro for C. This is trace-derived and replay-verified macro metadata; it is not a macro generated by [BASE_MODEL].

## Partial run results (2026-11-03)

The one-thread run recorded A/B/C for one task plus A for a second task. All four returned one token; latency was 524.6–776.7 seconds per call and none produced a usable JSON plan. A separate eight-thread A call on the same 314-token prompt took 649.6 seconds and also returned one token. The unreplicated 4.3% difference does not show a practical speedup. Both runs were stopped for low yield and their receipts/raw outputs were preserved in `generation_abc_run01` and `generation_abc_run02_threads8`. The comparison therefore has one shared task and zero valid plans; completion, execution, recovery and macro transfer benefit remain untested. This inference path is not parity-verified against streamed FP32 arithmetic.

From the repository root, the exact commands are:

```powershell
python experiments\expression_growth_001\operational_evaluation\run_generation_comparison.py prepare
python experiments\expression_growth_001\operational_evaluation\run_generation_comparison.py run --adapter-run experiments\expression_growth_001\impression_training\run02 --arms A B --output-dir experiments\expression_growth_001\operational_evaluation\generation_ab_run01 --cpu-threads 1
python experiments\expression_growth_001\operational_evaluation\run_generation_comparison.py run --adapter-run experiments\expression_growth_001\impression_training\run02 --macro-library experiments\expression_growth_001\learned_library\interpreter_library.json --arms A B C --output-dir experiments\expression_growth_001\operational_evaluation\generation_abc_run01 --cpu-threads 1
```

Run only one of the inference comparisons after active training and adapter verification have completed. Choose a new output directory for each attempt. Preparation and Python compilation do not load model weights or execute actions.
