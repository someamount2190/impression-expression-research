# IMPRESSION-002D Phase D — Pure-Torch Layer-0 Worker

## Implementation and dependency boundary

Added a separate pure-PyTorch operation module and a supervised layer-0 job. The worker implements RMSNorm, the Llama 3 RoPE frequency scaling and rotation, grouped-query key/value repetition, causal attention, residual paths, and SiLU-gated MLP directly with Torch. It does not import Transformers, Pandas, or PyArrow. The normal partition-batch worker path remains available.

Before importing Torch or materializing weights, the child validates the pinned revision, exact ordered embedding/layer-0 registered IDs, fixed saved `[1,8]` token IDs, Safetensors index and raw header metadata, BF16 shape/byte sizes, and the 20% RAM reserve. It computes a shape-derived activation working-set bound. The manager then enforces a minimum free-RAM threshold that preserves the reserve, activation bound, and explicit headroom while streaming one partition at a time.

Synthetic operator tests cover RMSNorm, Llama 3 inverse frequencies against the installed Transformers source formula without importing that module, RoPE zero-position behavior, GQA repeat, causal attention, and SwiGLU. RMSNorm follows the installed Llama order: normalize in FP32, cast back to activation dtype, then multiply by the weight in that dtype.

## Single bounded worker execution

One fresh worker executed one genuine layer-0 block with the fixed eight-token input saved by IMPRESSION-002B. It completed in 5.47 seconds, exited 0 with no NTSTATUS and empty stderr. Ten registered weight operations (embedding plus nine layer-0 partitions) each had load, compute, release, memory, and fingerprint telemetry. The final resident list was empty. `transformers_imported` was false.

The metadata preflight measured 13,640,404,992 B available and required 6,309,988,761 B before allocation:

- 4,983,970,201 B physical RAM reserve (20% of total)
- 788,017,152 B largest streamed partition (embedding)
- 1,130,496 B shape-derived activation working set
- 536,870,912 B explicit runtime headroom

The output activation is finite BF16 `[1,8,3072]`, stored as 49,152 raw bytes. SHA-256: `53e3256233349228f535d5b68f5fff4d7ecf03ea4402067828c171e7ae6646b0`. Peak sampled child RSS was 962,600,960 B. Full receipt and output bytes are under `diagnostics/worker/phase_d_layer0/`.

## Correctness boundary

The Phase B J artifact saved status and output shape but no layer-0 activation bytes or hash. Therefore the initial layer-0 run has no preserved independent J output to compare against. The result records `comparison.status=unavailable`; no independent parity claim is made.

The separate Phase B J evidence remains classified `completed_with_native_fault_warning`: that process returned success but its faulthandler stderr contained an access-violation stack during Transformers' lazy Pandas/PyArrow import. The Phase D worker did not import that stack.

## Repeated full CPU streamed forward

After review of the first receipt, a second full pass ran in a separate fresh child and immutable output directory using the same pinned revision, config, and saved eight-token IDs. Both passes completed without timeout, NTSTATUS, stderr, or a faulthandler/native access violation. Each ran 28 layers and 255 weight operations across 254 unique registered partitions; maximum concurrent residency was one and final resident sets were empty. Both receipts report no Transformers, Pandas, or PyArrow imports.

The first pass took 40.82 seconds inside the worker (44.19 seconds under the supervisor), with peak sampled RSS 1,170,489,344 B. Its preflight observed 13,642,293,248 B available and required 6,312,090,041 B, including the 4,983,970,201 B 20% reserve, 788,017,152 B embedding partition, 3,231,776 B activation working set, and 536,870,912 B explicit headroom. Minimum sampled parent-side available RAM was 12,636,446,720 B.

Each pass compared its outputs to preserved IMPRESSION-002B CPU streamed artifacts with a documented 0.0625 absolute tolerance. Both produced max, mean, and RMS absolute difference 0.0 for layer-27 hidden `[1,8,3072]` and logits `[1,8,128258]`. Direct comparison between fresh pass 1 and pass 2 also found byte-identical BF16 files: max/mean/RMS differences 0.0 for both artifacts. Logits SHA-256 is `4aafac4d1bd0aa6e01f8dbfa244ff870f8afc0960d189f862f49694d6058d277`; layer-27 hidden SHA-256 is `637714200467575b81b849487c82693fccc2579a5f7058bf4568e9fb73444e0a`.

The 002B references were generated by an earlier CPU streamed forward, not an independent full-model implementation. Repeatability and exact agreement with those saved artifacts strengthen implementation consistency but do not establish independent full-model parity. No performance gain was measured because no alternative placement or execution configuration was compared.

## Validation

`python -m pytest experiments/impression_002d/tests -q` passed 11 focused tests. `py_compile` passed for worker and test files; worker receipts and direct pass comparison parsed as JSON. No GPU, training, or checkpoint modification occurred. Both full forward passes were CPU-only.
